Content Performance Intelligence Using Machine Learning

A decision-support study for prioritizing content review using anonymized search and content-performance signals from the FlyRank ML Internship dataset.

1. Abstract

This project investigates whether a simple machine-learning approach can help identify content that may require review using observed search and content-performance signals. The analysis uses the anonymized repository dataset provided for the FlyRank ML Internship and evaluates a Logistic Regression model using a grouped validation design based on client_id. The final grouped validation produced an accuracy of 0.5785 and an F1 score of 0.5852, compared with 0.6382 accuracy and 0.6813 F1 under a random split. The lower grouped scores indicate that random splitting gives a more optimistic view of performance when records from the same client can appear on both sides of the split. The resulting model and ranked review queue are therefore presented as decision-support tools rather than as evidence of causal improvement or guaranteed future search performance.

2. Introduction / Problem Statement

Content teams may need to decide which pages should be reviewed, monitored, or investigated first. A large collection of content pages can make manual prioritization difficult.

This project explores whether available search and content signals can support a more systematic prioritization process. The intended decision is not to automatically change content, but to help a human reviewer identify pages that deserve additional investigation.

Research Question:

Can a simple machine-learning model identify declining versus non-declining content using safe search and content signals, and can those results support better content-review prioritization?

The analysis is observational. It does not claim that any individual search signal causes better or worse performance.

3. Data

Dataset Used

The analysis uses the anonymized CSV supplied inside the internship repository:

data/raw/content_refresh_anonymized.csv

The dataset contains approximately 30,000 rows and 44 columns.

The Hugging Face warehouse was not used because reliable access was unavailable. The repository CSV was therefore used consistently for the remaining analysis.

  • CTR

  • Scroll rate
  • AI traffic percentage

  • Days since last update

Public-Safe Handling

The project does not publish client names, domains, URLs, private search queries, credentials, or raw private exports. Content records are represented using anonymized identifiers.

Fields that directly represented the target or could reveal the target were excluded from the final model feature set.

4. Methodology

Model

The main model is Logistic Regression. Logistic Regression was selected because it is relatively simple, interpretable, and suitable for binary classification.

Target

The final validation task defines the target using the observed trend_direction field:

Positive class: declining content (trend_direction = down)
Negative class: non-declining content

The target field itself was not included as a model feature. Related outcome fields such as trend_pct were also excluded from the final feature set.

Feature Processing

  • Numeric content and search signals were selected.
  • Missing numeric values were handled using training-data medians.
  • Features were standardized before Logistic Regression.
  • The target and leakage-prone fields were excluded.

Validation Design

Two validation designs were examined:

  • Random 80/20 split
  • Grouped split by client_id

The grouped validation was treated as the more conservative estimate of cross-client generalization because clients in the training and testing sets do not overlap.

Grouped validation:
Training clients: 25
Testing clients: 7
Client overlap: 0

Leakage Check

A leakage audit was performed during the validation work. The audit passed, and the final model did not intentionally use the target field or directly derived target information as features.

Interpretation

The grouped validation result is lower than the random split result. This suggests that random splitting may provide an optimistic estimate when records from the same clients are distributed across training and testing data.

The grouped result is therefore the more useful conservative estimate for evaluating whether the approach can generalize across clients represented in the supplied dataset.

6. Limitations & Honest Framing

  • The analysis uses the repository CSV rather than the full Hugging Face warehouse.
  • The available CSV does not provide a sufficiently usable event-date structure for a true time-aware evaluation.
  • The target is based on observed trend direction and should not be interpreted as a guaranteed future outcome.
  • Search-performance signals such as impressions, clicks, CTR, and position can be correlated with one another.
  • The results are specific to the supplied dataset, selected features, target definition, and validation setup.
  • The model does not establish causal relationships.
  • The model should not be interpreted as evidence of how Google's ranking algorithm works.
Important: The model is a decision-support tool. It should not automatically publish, remove, rewrite, or change content. Human review is required before taking action.

7. Ranked Recommendations

The analysis can be converted into a practical content-review queue. The purpose of the queue is to help reviewers decide which pages deserve attention first.

Priority 1 — High-volume, low-CTR pages

Review pages that receive meaningful search exposure but show relatively low CTR. These pages can be investigated for possible content or presentation opportunities.

Priority 2 — Older content

Pages with a longer period since their last update can be considered for refresh review.

Priority 3 — Declining signals

Pages identified by the model as potentially declining can be added to a human-review queue for further investigation.

Example Reason Code

Reason Code Suggested Action
HIGH_VOLUME_LOW_CTR Review CTR opportunity
OLDER_CONTENT Consider refresh review
DECLINING_SIGNAL Investigate performance trend

These recommendations are prioritization suggestions only and require human review.

Final Takeaway

A simple Logistic Regression model can provide a structured way to prioritize content-review candidates using available search and content signals. However, the grouped validation result shows that performance is more modest when evaluated across unseen clients than under a random split.

The main value of this work is therefore not an automated content decision, but a reproducible framework for identifying pages that deserve human investigation.

Conclusion: Use the model to support prioritization and investigation — not as proof of causality or as an automatic content-action system.
